# Project Map: Where the Shared Integration Fits

## 1. VVU·IVE Evidence Runtime — first implementation

Purpose: explain why a claim is ready, blocked, inconclusive, or proven.

First figure: Evidence Instrument.
Inputs: authoritative status, reason codes, source/evidence IDs, timestamps, freshness, verification record link.
Do not: implement proof logic in the figure.

## 2. Proof Spatial Intelligence — second implementation

Purpose: transition from a map/asset selection to a detailed view of the selected equipment or system.

First figure: Spatial Asset (e.g. water-monitoring installation).
Inputs: selected asset ID, component topology, telemetry snapshot, status and provenance references.
Do not: replace the geographic engine or treat an isometric drawing as geographically accurate.

## 3. ProofBridge — third implementation

Purpose: make the collect → boundary-check → baseline → independence → export pipeline inspectable.

First figure: Evidence Pipeline Instrument.
Inputs: recorded stage results, verification IDs, reason codes and evidence references.
Do not: animate a stage as passed unless the authoritative stage result says it passed.

## 4. Agricultural edge system — fourth implementation

Purpose: show an edge node and monitored equipment alongside actual device health and measurements.

First figure: Edge Node / water system.
Inputs: device ID, sensor IDs, telemetry, measurement units, observed timestamps, connectivity/power state.
Do not: confuse requested actuator operation with telemetry-confirmed physical operation.

## 5. ProofBridge Micro-City — parallel educational use

Purpose: explain mechanisms and data flow through an interactive teaching model.

First figure: an educational mechanism with explicitly simulated data.
Do not: present game state as production evidence or real hardware telemetry.
