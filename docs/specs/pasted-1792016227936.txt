# PART 1 — THE WHOLE

## 1.1 The shared foundation

Five things are common to all environments. Nothing else.

| Shared | What it is | Why it is shared |
|---|---|---|
| **Artefact envelope** | The wrapper every environment uses at its boundary | So any environment can parse any other's output |
| **Status vocabulary** | A fixed set of state names | So status means the same thing everywhere |
| **Identity** | `environment_id` · `instance_id` · `operator_id` | So the origin of any artefact is unambiguous |
| **Cryptographic primitives** | SHA-256 digest · Ed25519 signature | So integrity is verifiable across boundaries |
| **Chain client** | A library that writes to and reads from the WORM ledger | So Bench records are consistent |

**Not shared:**

- Business logic
- Data stores
- UI
- Services
- Deployment configs
- Schedules

The shared foundation makes cooperation possible. It does not make any environment depend on another.

---

## 1.2 The artefact envelope

Every artefact that crosses an environment boundary carries this envelope. The content inside varies by type. The envelope does not.

```
envelope:
  envelope_version:      string       "1.0"
  artefact_id:           uuid
  artefact_type:         enum         see §1.3
  produced_by:
    environment:         enum         forge | bench | fire | field | press
    instance_id:         string
    operator_id:         string
    software_version:    semver
  produced_at:           ISO 8601 UTC
  content:               object       type-specific
  provenance:
    inputs:              list<artefact_id>
    policy:              string       optional
    configuration:       string       optional
  integrity:
    digest:              string       sha256:...
    signature:           string       ed25519:...   optional
    chain_ref:           string       optional
  status:                enum         see §1.4
  limitations:           list<string>
```

**Rules for the envelope:**

- `artefact_id` is stable. Never reassigned. Never reused.
- `produced_by.environment` is one of five values. Never combined.
- `provenance.inputs` is a list of upstream `artefact_id`s. Empty is valid.
- `integrity.digest` is always present. Signature and chain_ref are optional.
- `status` at export time describes the producing environment's assessment.
- `limitations` is a list of strings. Empty is valid.

**Nothing about the envelope implies the content is verified.** The envelope is a wrapper, not a claim.

## 1.4 The status vocabulary

Shared across all environments. Same words, same meaning, everywhere.

| Status | Meaning |
|---|---|
| `DRAFT` | Created locally. Not yet exported. |
| `IMPORTED` | Received by a receiving environment. Structure not yet checked. |
| `PARSED` | Structure understood. Content not yet validated. |
| `INTEGRITY_VALID` | Digest matches. Signature valid if present. |
| `VERIFIED` | Applicable verification policy satisfied. |
| `REJECTED` | Refused for a stated reason. |
| `INCONCLUSIVE` | Checked but the evidence does not establish the result. |
| `NOT_PROVEN` | Mandatory conditions not satisfied. |
| `BLOCKED` | A required operation could not proceed. |
| `EXPIRED` | Time-bounded validity has passed. |
| `SUPERSEDED` | A newer artefact replaces this one's authority. |
| `WITHDRAWN` | Producer has retracted it. |

**Rules:**

- `VERIFIED` is the strongest status. It requires a policy check.
- `NOT_PROVEN` does not mean false. It means not established.
- `REJECTED` and `NOT_PROVEN` are different. Rejection is a processing failure. Not-proven is a substantive finding.
- Status is never silently upgraded. A `PARSED` artefact becomes `INTEGRITY_VALID` only by running the integrity check.

---

## 1.5 Version negotiation

Every envelope declares `envelope_version`. Every receiving environment declares a set of supported versions.

**On receive:**

1. Parse `envelope_version` from the incoming artefact.
2. If it is in the receiver's supported set: accept and continue.
3. If it is not: reject with `REJECTED_VERSION_UNSUPPORTED`, stating the version received and the versions supported.
4. If it is a **newer minor version within the same major**: accept with `status: IMPORTED` and note the version mismatch in `limitations`.
5. If it is a **newer major version**: reject. Do not guess.

**Rule:** an environment never silently upgrades the trust status of an imported artefact because of a version match.

## 1.6 Failure semantics — the four questions

Every environment must answer all four, in writing, in its own specification.

| Question | Required answer |
|---|---|
| **What can it do without a network connection?** | The primary function must succeed offline. |
| **What happens when a shared service is unavailable?** | The environment must distinguish "unavailable dependency" from "negative result." |
| **How does it recover?** | Unfinished work is preserved. Interrupted operations are recorded. Resume is safe. |
| **How can the work move elsewhere?** | An export path exists that does not require another environment to be online. |

Failure to answer any of the four disqualifies the environment from being counted as independent.

**Purpose.** Physical-world sensing. Water, agriculture, industrial, mobile. Must work offline.

**Components.**

| Component | Role | Status |
|---|---|---|
| `FIELD OS · CARD.html` | Capture, queue, signature | ✅ exists |
| `Vvu-Field-Os-Pin.html` | Compact widget view | ✅ exists |
| `:3005 vvu-field` | Field sync service | ✅ evidenced |

**Produces.**

- `observation` — value, unit, sensor ID, measurement time, receipt time, calibration state, configuration version, integrity metadata

**Consumes.** None. Field does not need any other environment to function.

**API surface.**

- `POST /api/field/sync` — batch upload of queued observations
- `GET /api/field/status` — device health, queue depth, last sync
- Method on capture: `SIGNATURE` (per card's code)

**Failure modes.**

| Condition | Behaviour |
|---|---|
| Offline | Continue collecting. Queue locally. |
| Power loss | Preserve queue in durable storage. |
| Storage full | Refuse new captures. Alert. Preserve existing. |
| Sensor fault | Record observation with `sensor_state: FAULT`. Do not silently drop. |
| Calibration expired | Record observation with `calibration_state: EXPIRED`. |
| Sync failure | Preserve queue. Record failure. Retry with idempotency. |
| Duplicate submission | Return duplicate marker. Drop on device. |

**What Field owns:** the observation record, the local queue, the device identity, the calibration state.
**What Field does not own:** the interpretation of observations, the verification policy, the publication.

**Status:** ✅ second strongest. Needs the observation vocabulary formalised and the five status states made explicit.

# PART 3 — BUILD ORDER

The five environments have different states of readiness. This is the recommended sequence.

| # | What | Why this order |
|---|---|---|
| **1** | Shared foundation spec | Envelope, statuses, version negotiation. Nothing else can be built consistently without it. |
| **2** | **Fire** | Missing entirely. Blocks Route B and Route C. Smallest build of the five. Consumes existing assets. |
| **3** | Forge unification | Four components under one envelope. Not a rebuild — a wrapper. |
| **4** | Press editorial workflow | Claim extraction, receipt linkage, correction. Needed before any public claim is made. |
| **5** | Field vocabulary formalisation | Observation schema, five statuses. Low effort, high clarity. |
| **6** | Bench vocabulary formalisation | Rename only. Vocabulary already exists in the code. |

**Rule:** do not build #3 through #6 before #1 and #2. The envelope and Fire are the load-bearing pieces.

# PART 4 — THE INTEROPERABILITY DEMONSTRATION

The first end-to-end test that proves the architecture works:

1. **Forge** creates a claim. Exports it.
2. **Fire** imports the claim. Runs an adversarial test. Exports a `test_report`.
3. **Bench** imports the claim and the test report. Evaluates the evidence against a policy. Exports a `verification_receipt`.
4. **Press** imports the receipt. Prepares a publication that correctly represents its scope.
5. **Field** independently records a related real-world observation. Exports it when connectivity permits.

**The test passes if:**

- Each environment completes its job without any other being online at the same time
- Every artefact carries a valid envelope
- Every status is accurate to what was actually done
- No environment silently upgrades the trust status of an imported artefact

**If any of those four fails, the architecture is declared and not verified.**

---

# PART 5 — THE OPERATIONAL STANDARD

The governing statement for the entire estate:

> **Every environment owns its purpose, operations, data handling, and outputs. It must be capable of completing its primary job without requiring another environment to be available. It may exchange artefacts with other environments through documented contracts, preserving their identity, provenance, integrity information, and limitations. Receiving an artefact does not make its claims true, and exchanging an artefact does not transfer authority over the receiving environment's decisions.**

**Forge creates. Bench verifies. Fire challenges. Field observes. Press communicates.**

Each can work independently. Each can export its results. Each can interpret compatible work produced elsewhere.

The shared foundation makes cooperation possible. It does not make every environment dependent on a single operational sequence.
